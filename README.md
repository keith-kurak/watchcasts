# Tiny Podcatcher / "Podcast Duck"

A hybrid podcast app: an Expo (React Native, CNG) phone app and a native Wear OS
app. The phone app manages subscriptions; the watch syncs them over the Wearable
Data Layer and downloads episodes directly over its own Wi-Fi/LTE.

## Structure

```
podcast-app/
├── apps/
│   ├── mobile/          # Expo app (phone) — generated from `bun create expo`, CNG
│   └── watch/           # native Wear OS app (Kotlin + Compose for Wear OS)
├── packages/
│   └── shared/          # TS domain types + the Data Layer contract (phone side)
├── package.json         # bun workspaces (apps/mobile + packages/*)
├── tsconfig.base.json
└── .gitignore
```

`apps/watch` is intentionally **not** a bun workspace member — it's a standalone
native Gradle project, not a JS package. The workspace glob is scoped to
`apps/mobile` and `packages/*` for that reason.

## ⚠️ The one rule that links the two apps

The phone app and the watch app are companions only because they share the
**same applicationId** *and* are signed with the **same key**. Two places must
stay in sync:

| Side  | File                              | Value              |
| ----- | --------------------------------- | ------------------ |
| Phone | `apps/mobile/app.config.ts`       | `APPLICATION_ID`   |
| Watch | `apps/watch/gradle.properties`    | `appId`            |

Both are currently `dev.podcatch.app`. If they ever differ:
- the Wearable Data Layer won't deliver messages/data between the apps, and
- Google Play will reject the second APK uploaded under that package name.

**Signing:** if EAS manages the phone app's keystore, export it
(`eas credentials`) and point the watch's release signing at the *same* keystore
(`PODCATCH_KEYSTORE_PATH` etc. in `gradle.properties`, ideally via
`~/.gradle/gradle.properties` or CI secrets — never committed).

## Running

### Phone (Expo, CNG)

```bash
bun install            # from the repo root — sets up the workspace
bun mobile             # or: cd apps/mobile && bun start
```

Native dirs (`android/`, `ios/`) are generated by prebuild and are gitignored.
Run `bun --filter @podcatch/mobile expo prebuild` (or just build) to generate them.

### Watch (native Wear OS)

Open `apps/watch/` in **Android Studio**. It provisions the Gradle wrapper
(`gradlew` + `gradle-wrapper.jar`, which isn't committed), syncs the version
catalog, and downloads the SDK pieces. Then run on a Wear OS emulator or device.

> The Gradle version numbers in `gradle/libs.versions.toml` are a sane starting
> point — let Android Studio's upgrade assistant bring them current on first sync.

## The sync/download contract

`packages/shared/src/datalayer.ts` defines the Data Layer paths and keys. Because
the watch is Kotlin and can't import TS, the same contract is mirrored by hand in
`apps/watch/.../data/DataLayerContract.kt`. Keep the two in lockstep.

Flow:
1. Phone writes the subscription list to a `DataItem` at `/podcatch/subscriptions`
   (via `DataClient`).
2. `DataLayerListenerService` on the watch receives `onDataChanged`, persists to
   Room.
3. The watch enqueues a `WorkManager` job to download new episodes when it's on
   Wi-Fi + charging — downloading directly, not streaming files from the phone.
4. (Optional) If the watch has no direct connectivity, fall back to pushing audio
   from the phone via `ChannelClient`.
